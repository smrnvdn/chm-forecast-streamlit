# Прогноз часа максимума: единый интерфейс регионов

Одностраничный сервис на Streamlit с выбором региона. Доступны сохранённые помесячные прогнозы за январь—сентябрь 2026 года для Свердловской, Волгоградской и Вологодской областей и Пермского края. Это просмотр проверочных прогнозов, **не автоматическое формирование прогноза на новые сутки**.


## Выпуск сентября 2026

Сентябрь открывается по умолчанию для всех четырёх регионов: 22 рабочих дня, 264 допустимых часа и 88 выбранных часов на регион. Замерные интервалы: 8–15 и 18–21 МСК. Фактические ЧМ не загружены, дневные показатели попадания пустые; интерфейс не рассчитывает точность до публикации факта. Январь–август остаётся доступен в фильтре.

Для разработчика: для Свердловской области весь архив января—сентября 2026 приведён к единому правилу `M−2`: для месяца M обучение, факт потребления и все зависимые исторические признаки заканчиваются месяцем M−2. За январь—август после исправления получены Hit@2 `90/161 = 55,9%` и 2+2 `100/161 = 62,1%`; сентябрь не имеет опубликованных фактических ЧМ. Погода — наблюдения RP5 с интерполяцией как идеальный погодный proxy, не архив выпущенных прогнозов. Для Свердловской и Волгоградской областей используется опубликованный накануне ежедневный региональный план ATS `trade_region_spub`, цена покупки; это другой продукт, чем исторические месячные цены. Подробные паспорта — `data/forecast_*_september_2026_manifest.json` и `data/forecast_sverdlovsk_2026_manifest.json`; исходники, модели и технический отчёт хранятся в рабочем проекте `outputs/september_2026_release`.

Описание «О модели и данных» предназначено для бизнеса: модель, её входы, принцип выбора часов и правила чтения таблицы. История разработки и технические отчёты в пользовательский интерфейс не выводятся.

## Вологодская область: p000, 420 признаков без ветра

Снимок `data/forecast_vologda_2026.csv`: январь–август — 161 размеченный день, **2+2 90/161 = 55,90%, Hit@2 86/161 = 53,42%**. Сентябрь — 22 дня, 264 допустимых часа и 88 выбранных часов без факта и метрик. При добавлении сентября архивные метрики сохраняются: неизвестный факт не включается в знаменатель.

Замороженный рецепт: CatBoostRegressor RMSE, 320 деревьев, depth6, learning_rate0,03, L2=50, seed42. Обучение на 36 месяцах до начала M−1; собственная история каждой строки заканчивается M−2. Для сентября обучение 01.08.2023–31.07.2026. Погода RP5 WMO27037 Вологда (аэропорт), причинное перенесение последнего наблюдения максимум на 3 часа, остальные пропуски остаются NaN. Это ретроспективная демонстрация с наблюдённой погодой, а не подтверждённый заранее выпущенный прогноз.

Цена в обучении и сентябрьском расчёте одинакова по продукту: PVOLOGEN до 31.10.2023, ежедневная средневзвешенная цена покупки **Вологодской области** из `trade_region_spub` с 01.11.2023. Новая цена не заменяется ценой другого региона или зоны.

Распределение: `softmax(((score − day_mean) / day_sample_sd) / 0.5597418011577657)`, стандартное отклонение снизу ограничено 1e−6. Выбор двух вариантов преобразования сделан по июлю–ноябрю 2024 после настройки на январе–июне; окончательный параметр настроен по январю–ноябрю 2024. 2025–2026 для настройки преобразования не использованы. На январе–августе 2026 NLL 1,923 против 2,496 равномерного распределения; Brier 0,812 против 0,917. Это оценочные вероятности, точная калибровка не гарантируется. Сумма по допустимым часам дня равна 1, полный порядок часов и выбор 2+2 сохранены. Сам рецепт модели выбирался с просмотром 2026; этот год не является независимым тестом.

Исходный аудит, веса сентября и настройка вероятностей: `regions/vologda/reports/models/interface_release_v1` в рабочем проекте. Здесь опубликованы только проверенный снимок и два паспорта `data/forecast_vologda_*_manifest.json`. Другие регионы этим выпуском не пересчитывались.

## Пермский край: итоговый снимок E25

`data/forecast_perm_2026.csv` — 1 968 допустимых часов / 161 рабочий замерный день января–августа 2026. **2+2: 113/161 = 70,19%; Hit@2: 99/161 = 61,49%.** Финальный подбор из 21 новой конфигурации не улучшил основную метрику 2026: лучший вариант дал 111/161. Сохранена E25, CatBoostRegressor RMSE, 18 признаков, 120 деревьев, depth=5, learning_rate=0,05, L2=8, seed=20260929.

Все восемь месячных моделей воспроизведены с M−2 по потреблению и зависимому историческому профилю. Прогноз погоды представлен наблюдаемой/интерполированной погодой одной станции WMO 28224 как исследовательское допущение; РСВ не используется. Час h — интервал [h−1,h) МСК; местное время Перми = МСК+2. Только рабочие замерные дни и допустимые часы входят в прогноз.

Вероятности: `softmax(score / 0.5568046969582354)`. Преобразование выбрано и зафиксировано по январю–ноябрю 2024, 2025–2026 не использованы для калибровки. Порядок часов сохранён, сумма вероятностей за день равна 1. NLL на январе–августе 2026: 1,880 против 2,496 равномерного распределения; Brier: 0,779 против 0,917. Средняя масса вероятности выбранных по 2+2 часов — 61,61%, фактическая доля попаданий — 70,19%: точная калибровка не гарантируется. Рецепт модели выбирался после просмотра 2026, поэтому качество на этом периоде не является независимым подтверждением. Паспорт снимка и контрольные суммы — `data/forecast_perm_2026_manifest.json`.

## Возможности

- выбор региона и одного или нескольких доступных месяцев;
- метрики точности для выбранного периода: попадание модели при двух попытках и по схеме 2+2;
- матрица «дата × рыночный час» с оценочной вероятностью часа максимума; по допустимым часам дня сумма до округления равна 100%;
- синие ячейки — прогноз модели, зелёная ячейка — фактический час, галочка — попадание;
- два прогнозных часа при одном сегменте ЗЧ и по два часа в каждом сегменте при двух сегментах.

`data/forecast_2026.csv` — снимок CatBoost-79 для Свердловской области с единой отсечкой M−2. `data/forecast_volgograd_2026.csv` — снимок модели `m0399` (45 признаков) для Волгоградской области. Её оценки взяты из зафиксированного помесячного бэктеста, а выбранные часы и дневные метрики сверены с сохранёнными результатами. Исходные наборы и код обучения в этот Streamlit-репозиторий не входят.

Для Волгоградской области при прогнозе месяца M факт потребления в обучении заканчивается концом M−2. Фактические погода и РСВ целевого месяца в исследовании использовались как допущение об идеальном прогнозе/плане. Технические ограничения зафиксированы в паспортах данных; показанные результаты не являются проверкой качества реальных архивных прогнозов и не доказывают выполнение годового порога 64,2%.

Рыночный час в волгоградском снимке равен исходному нулевому индексу часа плюс 1. Час №1 — интервал 00:00–01:00 МСК. Модель сначала выдаёт `score` — предсказанное отклонение почасовой нагрузки от среднесуточного уровня; само по себе это не вероятность. Для общего интерфейса оценки преобразованы методом softmax в дневное распределение `probability`. Параметр преобразования выбран на ранних месяцах и окончательно рассчитан по фактам до ноября 2024 года; 2025–2026 годы не использовались для его подбора. Ранжирование часов и метрики Hit@2/2+2 при этом не меняются. Проверка соответствия процентов фактическим попаданиям находится в `../outputs/volgograd_probability_calibration_2026_09/` рабочего исследовательского проекта. Показанные проценты остаются оценочными, не гарантированными вероятностями.

## Локальный запуск

```bash
python -m venv .venv
source .venv/Scripts/activate  # Git Bash на Windows
pip install -r requirements.txt
streamlit run streamlit_app.py
```

## Публикация на GitHub

1. На GitHub создайте пустой репозиторий без README, `.gitignore` и лицензии.
2. В терминале из этой папки выполните:

```bash
git add .
git status
git commit -m "Initial Streamlit dashboard"
git branch -M main
git remote add origin https://github.com/<ваш-аккаунт>/<имя-репозитория>.git
git push -u origin main
```

Перед `git add .` проверьте, что в списке есть `data/forecast_2026.csv`, но нет `.venv/`, `outputs/` или `.streamlit/secrets.toml`. Если репозиторий уже имеет `origin`, замените команду добавления remote на `git remote set-url origin <URL>`.

> В CSV есть фактические часы максимума и результаты модели. До публикации публичного репозитория убедитесь, что это допускается политикой работы с данными.

## Развёртывание в Streamlit Community Cloud

1. Откройте [share.streamlit.io](https://share.streamlit.io/) и нажмите **Create app**.
2. Выберите GitHub-репозиторий, ветку `main` и файл `streamlit_app.py` в корне.
3. При желании в **Advanced settings** задайте понятный адрес приложения; секреты для текущей версии не нужны.
4. Нажмите **Deploy** и дождитесь запуска. Cloud установит зависимости из `requirements.txt`.
5. После каждого обновления данных или кода: выполните `git add .`, `git commit -m "..."`, `git push`. Community Cloud автоматически развернёт новую версию.

Для Cloud рекомендован Python 3.12. Дополнительные системные зависимости не требуются.

## Структура

```text
chm-forecast-streamlit/
├── .streamlit/config.toml  # тема
├── data/forecast_2026.csv                 # Свердловская область, CatBoost-79
├── data/forecast_volgograd_2026.csv       # Волгоградская область, m0399
├── data/forecast_volgograd_2026_manifest.json
├── data/forecast_perm_2026.csv            # Пермский край, E25
├── data/forecast_perm_2026_manifest.json
├── src/
│   ├── forecast_data.py                   # реестр регионов, загрузка и проверки
│   └── presentation.py                    # общая матрица и подсветка
├── tests/test_regions.py                  # проверки данных и переключения регионов
├── streamlit_app.py                       # точка входа
├── requirements.txt
└── .gitignore
```

Для добавления следующего региона подготовьте снимок с теми же полями даты, рыночного часа, сегмента, выбранных часов, факта и дневных метрик; затем добавьте его описание в `src/forecast_data.py` (`REGIONS`) и режим отображения оценок при необходимости. Проверки должны подтвердить по одному фактическому максимуму на дату, уникальность часов, корректность выбора 2+2 и совпадение метрик с исходным бэктестом. Новые прогнозы на ещё не завершившиеся дни потребуют отдельного процесса подготовки входных данных и запуска модели; данный интерфейс не подставляет вместо них будущий факт.

Локальная проверка после обновления данных или кода:

```bash
python -m unittest discover -s tests -v
```
